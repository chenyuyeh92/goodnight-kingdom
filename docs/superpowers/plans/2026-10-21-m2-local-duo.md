# 第二步「同機雙人」實作計畫

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 測試靶場支援同一台鍵盤兩人遊玩:開場選單人或雙人、兩個角色各自操作、鏡頭照顧兩人、愛心與受傷、一人睡著後在隊友身邊復活、兩人都睡著就從檢查點重來。

**Architecture:** 延續第一步的做法:規則(愛心、復活與重來的判斷、檢查點、雙人鏡頭、依模式分配輸入)寫成不依賴 Phaser 的純函式並以 Vitest 測試;把目前寫死在場景裡的單一角色抽成 `PlayerEntity`,場景改為管理一組角色。重來用 `scene.restart()` 帶著檢查點重建整個場景,避免手動重設遺漏狀態。

**Tech Stack:** 同第一步(Phaser 4.2.1、TypeScript 5.9.3、Vite 8.3.0、Vitest 5.0.3、@playwright/test 1.63.0)。

**Spec:** `docs/superpowers/specs/2026-10-20-goodnight-kingdom-design.md`(第 3 節第 2 步;第 1 節「三顆愛心、用完從檢查點重來」;4.3 被打中扣愛心與短暫無敵;4.4 雙人鏡頭;4.5 雙人復活規則)

## Global Constraints

- 沿用第一步計畫 `docs/superpowers/plans/2026-10-20-m1-feel-prototype.md` 的 Global Constraints(版本固定、`base`、960×540、繁體中文、色塊佔位、不收集資料、commit 結尾兩行、git 身分、分支 `claude/ai-game-dev-workflow-dqbe1t`)。
- 按鍵(已實測定案):玩家 A = `KeyA`/`KeyD`/`KeyW`/`KeyS`、射擊 `KeyC`、跳躍 `KeyV`;玩家 B = 方向鍵、射擊 `Comma`、跳躍 `Period`。
- 單人模式:兩組按鍵都操控同一個角色(第一步的行為不變)。雙人模式:A 組只操控玩家 A,B 組只操控玩家 B。
- 愛心:每人 3 顆。被打中扣 1 顆,之後無敵 1000ms 並閃爍。
- 一人愛心用完會「睡著」;隊友還醒著時,3000ms 後在隊友上方從畫面頂端掉下來復活,復活後愛心補滿並無敵 1500ms。
- 所有人都睡著(單人模式就是唯一的角色睡著)後 800ms,從最近到達的檢查點重來。
- 鏡頭只往前推;兩人都不能離開畫面(左右各留 16px)。
- 玩家的子彈不會打到玩家。
- 角色顏色:玩家 A `#ffd27a`、玩家 B `#9be7c4`;頭上顯示「A」「B」(單人模式不顯示)。

## Review Focus

1. **一人往前衝、另一人站著不動:** 鏡頭停在讓落後者仍在畫面內的位置,領先者被畫面右緣擋住,不會把落後者推出畫面或推著走 → `advanceTeamCamera` 以落後者限制捲動。測試在 Task 1。
2. **隊友蹲在低矮通道或站在平台上時復活:** 復活的角色不能卡進地形 → 從畫面頂端(y=40)在隊友的 x 位置掉下來,自然落在地形上。測試在 Task 5(e2e:在通道內觸發復活後角色 `y` 最終等於地面或天花板頂面,且之後能移動)。
3. **無敵期間、睡著時或同一格同時碰到兩個荊棘:** 只扣一顆愛心 → `applyHit` 在無敵或睡著時不扣。測試在 Task 1。
4. **睡著的角色的按鍵仍被按住:** 睡著的角色不動、不射擊,也不影響鏡頭 → 場景跳過睡著角色的輸入,`advanceTeamCamera` 只用醒著角色的 x。測試在 Task 5(e2e)與 Task 1(鏡頭)。
5. **兩人在同一格先後睡著,或單人睡著:** 只觸發一次重來,重來後愛心全滿、角色在檢查點、鏡頭從檢查點重新開始 → `decideTeam` 純函式與場景只在 `restart` 動作時重啟一次。測試在 Task 1 與 Task 5。

**Interfaces:**
- Consumes:`MAX_DT_MS`(`src/config/tuning.ts`)、`advanceCamera`(`src/game/camera.ts`)。
- Produces(`health.ts`):
  ```ts
  export const MAX_HEARTS = 3;
  export const HIT_INVULN_MS = 1000;
  export const REVIVE_DELAY_MS = 3000;
  export const REVIVE_INVULN_MS = 1500;
  export const RESTART_DELAY_MS = 800;
  export interface Health { hearts: number; invulnMs: number; down: boolean; downMs: number; }
  export function freshHealth(invulnMs?: number): Health; // hearts 3, down false, downMs 0
  export function applyHit(h: Health): { health: Health; hit: boolean; wentDown: boolean };
  export function tickHealth(h: Health, dtMs: number): Health; // dt 夾到 MAX_DT_MS;invulnMs 遞減不低於 0;down 時 downMs 累加
  ```
  `applyHit`:`down` 或 `invulnMs > 0` → 原樣、`hit false`;否則 `hearts - 1`、`invulnMs = HIT_INVULN_MS`;`hearts` 變 0 時 `down = true`、`downMs = 0`、`wentDown true`。
- Produces(`team.ts`):
  ```ts
  export type TeamAction = { kind: 'none' } | { kind: 'revive'; index: number } | { kind: 'restart' };
  export function decideTeam(healths: readonly Health[]): TeamAction;
  export function reachedCheckpoint(checkpoints: readonly number[], maxReachedX: number): number;
  ```
  `decideTeam`:全部 `down` 且每人 `downMs >= RESTART_DELAY_MS` → `restart`;全部 `down` 但未滿 → `none`;否則回傳第一個 `down && downMs >= REVIVE_DELAY_MS` 的 `revive`;都沒有 → `none`。
  `reachedCheckpoint`:回傳 `<= maxReachedX` 的最大檢查點;都沒有則回傳 `checkpoints[0]`。
- Produces(`camera.ts` 新增):
  ```ts
  export function advanceTeamCamera(prevScrollX: number, xs: readonly number[], viewW: number, worldW: number, leadRatio: number, margin: number): number;
  ```
  `xs` 為空 → 回傳 `prevScrollX`。否則 `focus = 平均(xs)`,`wanted = advanceCamera(prev, focus, viewW, worldW, leadRatio)`,再以 `max(prev, min(xs) - margin)` 為上限。
